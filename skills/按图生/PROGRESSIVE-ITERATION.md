# 渐进式迭代 Prompt 规则（中文 JSON 模式）

## 1. 渐进式迭代 Prompt JSON Schema

**核心原则**：渐进式迭代不是"重新生成"，而是"微调当前结果"。迭代 prompt JSON 在标准 prompt schema 基础上增加 `迭代` 字段。

```json
{
  "迭代": {
    "模式": "渐进式",
    "保持": "string (一句话描述当前结果中要保持不变的核心特征)",
    "调整": [
      {
        "目标": "string (要调整的具体元素或字段)",
        "方向": "string (具体调整方向)",
        "强度": "极小 | 细微 | 适度 (限制强度)",
        "绝对目标": "string (V3.2 教训 1：用绝对正向句式描述目标状态)"
      }
    ],
    "边界": [
      "string (设置边界，避免过度调整)"
    ]
  },
  "主体": { ... },
  "风格": { ... },
  "装饰元素决策": [ ... ],
  "排除": [ ... ],
  "输出": "单张图片"
}
```

### 1.1 五条铁律（中文 JSON 模式）

| 铁律 | JSON 字段体现 |
|---|---|
| 1. 强调保持 | `迭代.保持: "扁平插画风、简约、轻盈的整体风格"` |
| 2. 限制强度 | `迭代.调整[].强度: "极小"` |
| 3. 设置边界 | `迭代.边界: ["不要过强", "避免过度立体感"]` |
| 4. 明确基准 | `迭代.保持` 同时承担"保持柔和"等基准描述 |
| 5. 标准结尾 | `输出: "单张图片"` |

### 1.2 为什么需要这 5 条？

**问题场景**：用户已经生成了 4 张图，大部分满意，只是觉得"缺少磨砂玻璃质感"

**错误做法（自然语言时代）**：
```
增加底部透明层的磨砂玻璃质感（半透明、毛玻璃模糊效果）。
白色图标符号增加细微投影，增加立体感。
增强右上方高光反射，增加材质光泽感。
```

**为什么会出问题**：
- 只说"增加""增强"，没有限制强度
- 豆包不知道基准，会理解成"加强到很明显"
- 导致过度调整，偏离参考图的克制风格

**正确做法（中文 JSON 模式）**：

```json
{
  "迭代": {
    "模式": "渐进式",
    "保持": "扁平插画风、简约、轻盈的整体视觉",
    "调整": [
      {
        "目标": "底部透明层",
        "方向": "增加磨砂玻璃质感",
        "强度": "极小",
        "绝对目标": "底部层呈现极轻的毛玻璃模糊效果，几乎只是若有若无的雾感"
      },
      {
        "目标": "白色图标符号",
        "方向": "增加投影",
        "强度": "极小",
        "绝对目标": "图标符号下方有约 1-2px 的极淡灰色投影，几乎看不见"
      }
    ],
    "边界": [
      "不要强烈高光或镜面反射",
      "不要明显 3D 体积",
      "整体保持扁平 icon 的轻盈感"
    ]
  },
  "主体": { ... },
  "风格": { ... },
  "排除": [
    "强烈镜面高光",
    "明显 3D 阴影",
    "厚重材质纹理"
  ],
  "输出": "单张图片"
}
```

**结果**：豆包知道"在当前基础上微调"，不会过度调整。

**场景**：生成了火焰图标，风格基本对了，但缺少磨砂玻璃层次

## 2. V3.2 加固：4 条 prompt 写作核心教训

**5 条铁律**（1.1）解决 prompt **结构问题**；本节 4 条教训解决 prompt **内容问题**——堵 V3.1 实验暴露的几种反向退化模式（耳机 case Round 2 退化、Round 3 镜头光晕）。

### 教训 1：绝对目标 > 方向（V3.2 关键）

**问题**：用 `方向: "减弱体积感"` 这种 reduction 指令，模型对"减弱"的理解不可控，可能**反向**（如：要求"减弱体积感"，模型反而加横向反光条纹来强化层次感）。

**正确**：用 `绝对目标` 字段以**绝对正向**句式描述**目标状态**，而非描述变化方向。

| ❌ 反例（方向 用 reduction） | ✅ 正例（绝对目标 用绝对正向） |
|---|---|
| `方向: "减弱体积感"` | `绝对目标: "完全降级为色块拼贴 + 单色平涂"` |
| `方向: "减弱高光"` | `绝对目标: "完全是单色平面，无任何 highlight"` |
| `方向: "减少反射"` | `绝对目标: "全面哑光，所有表面平涂无反射"` |
| `方向: "减少厚度"` | `绝对目标: "扁平 paper-thin 效果，所有层均为零厚度色块"` |

**根因**：模型的语言理解里，"减弱 X" 是相对量（不知道从多少减到多少），绝对描述是绝对状态（明确知道目标长什么样）。

### 教训 2：一轮只改一类事

**问题**：`调整` 数组里同时放 3 个独立维度（如体积+高光+色调），模型会过度修正或混乱。

**正确**：把**相关变化合并为同类**，归到 `调整` 的同一项里（如"扁平化" = 减体积 + 减高光，因为两者都是"减少 3D 渲染"的不同表现）；**不相关维度**单列为次要项或留下轮处理。

**示例（耳机 case Round 4 成功 prompt）**：

```json
{
  "迭代": {
    "调整": [
      {
        "目标": "整体材质",
        "方向": "完全扁平化",
        "强度": "适度",
        "绝对目标": "所有面均为单色平面色块拼贴，无体积感、无高光、无明暗"
      },
      {
        "目标": "色调",
        "方向": "色相微调偏蓝紫",
        "强度": "极小",
        "绝对目标": "整体偏蓝紫色调约 5%"
      }
    ]
  }
}
```

第一项是主目标（强 绝对目标），第二项是次要目标（弱 极小）。

### 教训 3：预防性排除——更宽的排除清单

**问题**：`排除` 只排除"已知会出现的元素"（如反光条纹），**不排除"模型可能自创的新元素"**（如镜头光晕），导致下一轮冒出新瑕疵。

**正确**：`排除` 数组里列出**所有同类的可能局部强光元素**，一次性显式排除。

| ❌ 反例 | ✅ 正例 |
|---|---|
| `排除: ["反光条纹"]` | `排除: ["反光条纹", "高光带", "镜头光晕", "亮斑", "亮色条纹", "任何局部高亮", "轮廓光", "边缘发光"]` |
| `排除: ["书页"]` | `排除: ["书页", "书脊", "书签", "装订线", "任何分层堆叠结构"]` |

**思考方法**：写完 `排除` 后问自己"模型还能在这个维度上加什么不期望的元素？"——把答案也加进 `排除`。

### 教训 4：策略 B 反向退化时，--ref 应回退到最干净的基底

**问题**：策略 B 默认用上一轮（最新轮）作 `--ref`，但**如果上一轮是退化版本，会从退化基础上继续退化**。

**正确**：**主流程**检测到反向退化时（本轮比上轮新增 unwanted 元素），在下轮生成命令里**显式 override --ref 路径**，回到**退化前最干净的那一轮**。

**触发条件**：当评审发现"本轮比上轮新增 unwanted 元素"时——
- 不要默认走"Round N 作 Round N+1 基底"流程
- 在生成命令里 explicitly：`--ref <指定的干净轮次路径>`
- 评审 skill 只负责报告退化，不负责决定回退哪一轮；由主流程根据评审结论判断

**示例（耳机 case 应用本教训）**：
- Round 1 → 微小差异 → 修订
- Round 2 → 反向退化（新增条纹）→ 修订，但主流程决定下轮用 Round 1 作 --ref，避免连续退化
- Round 3 → 修复条纹但仍有差异 → 修订
- Round 4 → 显式用 Round 1 作 --ref + 应用教训 1/2/3 写更精确 prompt → **通过 级**

> **注**：评审 skill 当前**不会**自动检测退化并 override --ref（为维持复杂度），由**主流程**根据评审结论自行判断是否回退基底。

## 3. 一句话总结

**迭代.保持 / 调整 / 边界 三字段管结构（保持/限制/边界），绝对目标 字段管内容（教训 1）；调整 数组合并同类项（教训 2）；排除 数组更宽地排除（教训 3）；退化时主流程显式回退 --ref（教训 4）。所有字段中文，豆包直接读，无需翻译。**
