# 风格分类卡 (STYLE-CARD) — 中文 JSON Schema 版

「按图生」与「按图生-评审」共享的**机器可读分类卡 schema**。

## 它解决什么

让评审者和 prompt 作者**先单独给每张图打分类标签，再做机械比对**——而不是凭"整体感觉相似"自由判断。这样做：

- prompt 阶段：先填参考图分类卡（中文 JSON），再据此写 prompt（中文 JSON），避免起点描述错（如把扁平 icon 误描述成"立体微浮雕"）
- 评审阶段：独立填两张卡的 JSON（参考图 + 生成图），任一字段不一致 → 机械判定 FAIL，无自我说服空间
- 全流程中文 JSON 化后：可脚本化校验、做 round-diff、做机械比对，且豆包能直接读懂中文字段不需要再做语义解码

## 核心原则

1. **独立填写**：先给参考图填一份完整 JSON 卡，再独立给生成图填一份完整 JSON 卡。**禁止边对比边填**——那等于回到"整体感觉判断"
2. **机械锚点**：每个字段都给"看到 X 就选 Y"的识别锚点，不是主观打分
3. **互斥枚举**：每个字段只能选 1 个枚举值（必要时辅以子字段补充关键词），不允许"既是 A 也是 B"
4. **不知道就停**：如果某字段在锚点里找不到对应值（罕见风格），停下来如实写 `"未知"` 并在 `备注` 字段说明原因——禁止硬塞最像的那个
5. **全中文输出**：字段名 + 枚举值 + 描述全部用中文。豆包/评审都直接读中文，不要英文 codename

## 分类卡 JSON Schema（中文）

```json
{
  "卡类型": "参考图 | 生成图",
  "任务ID": "string (任务唯一 ID)",
  "轮次": 1,
  "图片路径": "string (绝对路径)",
  "风格": {
    "维度": "二维扁平 | 三维渲染 | 摄影 | 手绘",
    "渲染": "矢量图标 | 风格化 | 写实 | 超现实",
    "光影": "无光影 | 仅渐变 | 柔光 | 棚拍光 | 戏剧光",
    "媒介": {
      "主": "扁平UI | 磨砂玻璃 | 黏土 | 塑料 | 金属 | 纸张 | 布料",
      "次": "string | null"
    },
    "填充模式": {
      "值": "实心填充 | 线性描边 | 混合填充",
      "描边连续性": "string | null"
    },
    "边缘": {
      "锐度": "硬边 | 柔边",
      "接地": "浮空 | 接地",
      "背景虚化": false
    },
    "构图": "居中铺满 | 居中紧凑 | 居中留白 | 非居中",
    "背景": "纯白 | 纯透明 | 纯色 | 柔和渐变 | 强对比渐变 | 场景",
    "配色": {
      "色卡": [
        {
          "颜色": "string (具体颜色描述，如 '深蓝黑色' / '亮草绿色' / '纯白')",
          "占比": "主导 | 次要 | 点缀 (按视觉面积估算)",
          "当前载体": "string (该颜色在参考图里附着在哪个元素上，仅供描述/迁移决策参考——不是颜色的归属)"
        }
      ],
      "主色": "string (色卡里 占比=主导 的那一项颜色)",
      "点缀色": "string | null (色卡里 占比=点缀 的那一项颜色，多个用顿号分隔)"
    }
  },
  "装饰元素": [
    {
      "编号": "el_1",
      "描述": "string (客观描述：形状/位置/材质)",
      "参考图语义": "string (该元素在参考图主题下的语义解读)",
      "主题相关": true
    }
  ],
  "备注": "string (未知 字段的原因说明，可选)"
}
```

## 字段填写指南

### `风格.维度` — 画面维度

> 画面表达的是 2D 平面还是**真三维渲染**？**只有这两档，没有"2.5D"中间档。**

| 枚举值 | 机械识别锚点 |
|---|---|
| `二维扁平` | 不是「渲染器/相机产出的真 3D 体积」的一切——**含带手绘光影的扁平图标**（有小投影/小高光/浮雕感/渐变受光面，但这些是设计师手绘铺出来的假立体，不是连续物理光照模型）；像 Figma/AI 矢量图标、Notion emoji、轻拟物 icon 全部归这一档 |
| `三维渲染` | **真** 3D 渲染：完整体积回转体、连续物理光照、明确受光面/背光面、真实接触阴影、材质反光；像 Blender/C4D 渲染图、黏土微缩。判据是"这是渲染器/相机产出的"而非"设计师手绘出来的" |
| `摄影` | 真实摄影或仿真实摄影，有真实景深、光圈虚化、自然光 |
| `手绘` | 手绘笔触可见，有铅笔/水彩/马克笔的非均匀质感 |

**⚠️ 铁律：禁用「二点五维 / 2.5D / 二点五维分层」——已从枚举里删除。**

**为什么删（根因）**：扁平图标常带手绘光影（小投影、高光、浮雕感），过去容易被误判成「二点五维分层」；一旦维度卡填了 2.5D、prompt 里出现"2.5D/二点五维/浅浮雕"，**豆包会真的把它渲染成 soft-3D 饱满立体物**（实战翻车：靶心图标被生成成饱满立体回转盘）。手绘光影 ≠ 真 2.5D。**维度只有一个二元判断：是不是渲染器/相机产出的真三维？是 → `三维渲染`；否（哪怕带一堆手绘光影）→ `二维扁平`。**

**关键判别**：
- 唯一要问的问题：**这个立体感是"渲染器/相机产出的真体积"，还是"设计师手绘铺的假立体"？** 真渲染 = `三维渲染`；手绘假立体（含参考图那种带渐变高光投影的扁平图标）= `二维扁平`
- 看**光照**——几档手绘平滑铺色/柔和渐变（哪怕有小高光小投影）= `二维扁平`；连续物理光照 + 材质反光 + 真实接触阴影 = `三维渲染`
- **不要被"有立体线索"迷惑**：小投影、高光、浮雕感、渐变受光面**都可以是手绘扁平**，有这些不等于 3D，更不等于要写成 2.5D
- **不要被颜色迷惑**：紫色 + 圆角 + 渐变可以是任意一种维度

### `风格.渲染` — 渲染等级

| 枚举值 | 机械识别锚点 |
|---|---|
| `矢量图标` | 几何符号化，元素抽象为图标符号；尺寸缩到 32px 仍可辨识 |
| `风格化` | 风格化但有体积，元素仍可识别但被夸张/简化（黏土风、Q 版、卡通 3D） |
| `写实` | 写实，元素质感接近实物 |
| `超现实` | 超现实/概念，元素或场景违反物理常识 |

### `风格.光影` — 光影系统

| 枚举值 | 机械识别锚点 |
|---|---|
| `无光影` | 完全无光影，纯色块平铺 |
| `仅渐变` | 仅靠色块内部渐变制造层次，无明确光源方向 |
| `柔光` | 有柔和的方向性光照，明暗面平滑过渡，无锐利高光 |
| `棚拍光` | 有明确光源 + 高光斑 + 投影，像产品摄影棚布光 |
| `戏剧光` | 强对比光影，明显明暗剪影、冷暖光对撞 |

**关键判别**：看**最亮处**——没有可见高光斑 = 无光影/仅渐变；有但柔和 = 柔光；有清晰高光斑 = 棚拍光。

### `风格.媒介` — 媒介质感

`媒介.主` 必填，`媒介.次` 可选（描述次要叠加材质）。

| `主` 枚举值 | 机械识别锚点 |
|---|---|
| `扁平UI` | 扁平 UI 矢量，无任何质感（纯色 + 渐变） |
| `磨砂玻璃` | 毛玻璃/磨砂玻璃，半透明 + 模糊背景 |
| `黏土` | 黏土/橡皮，哑光柔软质感 |
| `塑料` | 塑料，有清晰高光斑、表面光滑 |
| `金属` | 金属，强反射或拉丝 |
| `纸张` | 纸/卡纸，有纤维或剪纸边缘 |
| `布料` | 布料/毛绒 |

`次` 写成中文字符串如 `"磨砂玻璃叠加层"` / `"塑料顶部高光"`，无叠加层时填 `null`。

### `风格.填充模式` — 填充模式（关键字段）

> 主体元素是**填充实心**还是**线性描边**？

| `值` 枚举 | 机械识别锚点 |
|---|---|
| `实心填充` | 元素是色块填充，内部不可见背景；典型填充 icon、扁平插画主体 |
| `线性描边` | 只有描边/线条，元素内部是空的（透明或同背景色） |
| `混合填充` | 主体填充 + 局部线描叠加 |

**关键判别**：
- 盯着主体**内部**——能看到背景透过来 = `线性描边`；看不到 = `实心填充`
- 把图缩小到 16px 看轮廓——能看到一圈细线包围一片空白 = `线性描边`；看到一坨实色 = `实心填充`
- **本字段一票否决**：填充模式错了，所有其他字段对了也是废图

**⚠️ 实心填充也要查「内部留白镂空」（V5.8 新增，实战翻车血泪）**：`实心填充` / `混合填充` 的图标**常在实心色块内部挖空出留白**——透出底色/白色的空心区域，用来勾出符号或结构（参考图 Σ 是实心方块里挖出的**白色镂空线条**；汽车案例的**车窗是车身色块里的镂空留白**）。这个「实心色块 + 内部留白挖空」的关系是很多扁平图标的灵魂，但填卡/生成时**极易被做成一整块纯实心剪影而丢掉**（豆包默认倾向填死内部）。
- **填卡纪律**：判定 `实心填充` / `混合填充` 后，必须再盯一眼主体内部——**有没有透出底色的镂空留白区域？** 有 → 在 `描边连续性` 字段（`混合填充` 时）或 `备注` 里显式写明"内部有镂空留白：XX 处（如车窗/符号/中缝）"，别只写"实心填充"就完事。
- **写 prompt 纪律**：参考图有内部镂空留白时，B 档 `填充模式` 描述必须点出"车身/主体实心填充 + 内部 XX 做镂空留白（透出底色）"，并在 `排除` 里列 `"实心填死的车窗/内部"`；否则生成图会变纯实心剪影、丢掉留白关系（汽车案例第 5 轮就因没写镂空、被用户"留白部分呢"打回补第 6 轮）。

**`描边连续性` 字段强制要求**（V3.1 加固）：

`填充模式.值 === "线性描边"` 时，`描边连续性` 必填，描述描边段数 + 连续性形态。例如：

```json
"填充模式": {
  "值": "线性描边",
  "描边连续性": "一笔连续闭合，4 段边一气呵成回到起点"
}
```

```json
"填充模式": {
  "值": "线性描边",
  "描边连续性": "多段短线分立，由约 N 段独立短线组成，典型虚线/破折线风格"
}
```

```json
"填充模式": {
  "值": "线性描边",
  "描边连续性": "右上方有意识开口约 X°，作为'外发'语义视觉锚点"
}
```

**纪律**：段数 / 断口位置必须真数过的，不允许凭印象。`填充模式.值 !== "线性描边"` 时 `描边连续性` 应填 `null`。

### `风格.边缘` — 边缘 & 投影

```json
"边缘": {
  "锐度": "硬边 | 柔边",
  "接地": "浮空 | 接地",
  "背景虚化": false
}
```

| `锐度` | 机械识别锚点 |
|---|---|
| `硬边` | 边缘硬朗清晰，无虚化；矢量切割感 |
| `柔边` | 边缘有微小柔化（抗锯齿之外的柔焦） |

| `接地` | 机械识别锚点 |
|---|---|
| `浮空` | 主体悬浮，无任何地面接触阴影 |
| `接地` | 主体下方有明确接触投影/地面阴影 |

`背景虚化` 写实/摄影类有景深虚化时为 `true`。

### `风格.构图` — 主体占比 & 留白

| 枚举值 | 机械识别锚点 |
|---|---|
| `居中铺满` | 主体占画布 ≥60%，背景几乎被压满 |
| `居中紧凑` | 主体占 30-60%，四周有适度留白 |
| `居中留白` | 主体占 ≤30%，画面大量留白（呼吸感强） |
| `非居中` | 主体不居中（参考图本身就是非对称构图） |

**关键判别**：
- 看**主体外接矩形相对画布的面积比**：肉眼估到 30% / 60% 档位即可
- 跨档差 1 档允许（如 居中紧凑 ↔ 居中留白 相邻），跨 2 档 → 修订

### `风格.背景` — 背景类型（关键字段）

| 枚举值 | 机械识别锚点 |
|---|---|
| `纯白` | 纯白底（#FFFFFF），无任何渐变/纹理 |
| `纯透明` | 透明底（PNG alpha 通道，需明确确认） |
| `纯色` | 纯色底但不是白（如米色、浅紫等） |
| `柔和渐变` | 柔和渐变（如紫到粉、米黄到暖橙） |
| `强对比渐变` | 强对比渐变（霓虹色对撞、暗黑过渡） |
| `场景` | 有完整场景（自然环境、室内、抽象空间） |

**关键判别**：背景判错是**下游 rembg 抠图崩边缘**的常见根因。同档内细节差异允许；类型不一致 → 修订。


### `风格.配色` — 配色构成（独立于载体，V4.2 核心字段）

> 参考图的**色卡构成**——把哪些颜色 + 各自占比 enumerate 出来，**形态描述（哪个元素是什么颜色）与色卡构成彻底解耦**。

**为什么独立列**：当前 skill 之前把"颜色"和"载体"绑定写成 `"深蓝黑色描边 + 亮绿色填充"`——一旦"描边"这个**形态**被装饰元素决策移除，深蓝黑色这个**颜色构成**也跟着丢了，整张图的色卡被破坏。色卡是参考图的**视觉调性核心**，独立于具体元素，必须独立维护。

**结构**：

```json
"配色": {
  "色卡": [
    {"颜色": "深蓝黑色", "占比": "次要", "当前载体": "外层方形描边"},
    {"颜色": "亮草绿色（含深浅两档）", "占比": "主导", "当前载体": "内部山峰、太阳"},
    {"颜色": "纯白", "占比": "点缀", "当前载体": "外框内底"}
  ],
  "主色": "亮草绿色",
  "点缀色": "深蓝黑色、纯白"
}
```

**填卡纪律**：
1. **色卡数组必须 enumerate 出参考图里所有视觉上能识别的独立颜色**——包括外框颜色、背景颜色、装饰颜色，每一种都列。不允许把多种颜色合并写成 `"深蓝黑描边 + 亮绿色填充"`
2. **`占比` 必须填**——按视觉面积估算：主导 = 占视野 >40% / 次要 = 10%~40% / 点缀 = <10%。这决定了下游 prompt 阶段哪些颜色是"不能丢的不变量"
3. **`当前载体` 仅供描述**——是颜色目前附着在哪个元素上，**不是**颜色的归属。当 prompt 阶段移除/替换该载体时，色卡里的颜色不会跟着消失，必须找新载体或加入剪影主体本身
4. **`主色` / `点缀色`** 是 `色卡` 数组的衍生字段，自动从 `占比` 推导：主导 → `主色`；点缀 → `点缀色`；次要 → 默认写入 `点缀色`（多个用顿号分隔）

**色卡的不变量地位**（重要）：
- `色卡` 数组里每一种颜色都是参考图的**视觉调性 DNA**
- 任何 prompt 阶段（含装饰元素决策、迭代、用户吐槽反馈）**都不能让 `占比: 主导` 或 `占比: 次要` 的颜色从生成图里消失**
- 如果消失了，等于生成图色卡偏离参考图，视觉调性必然不一致——评审 Step C 必须把它列为关键差异（即使其他风格字段全一致）
- 详见下方"装饰元素决策铁律"

### `装饰元素` — 装饰元素清单（主题迁移决策用）

> 参考图中**所有非主体的装饰/辅助元素**及它们在参考图主题语境下的语义解读。

`风格.*` 是**风格层**描述（主题无关，可以无脑迁移）；`装饰元素` 是**主题层**描述（参考图特定主题的产物，迁移时必须重新判断是否成立）。

**为什么单独列**：当前 skill 之前把参考图当成"纯风格容器"，所有元素无差别迁移，导致"风格 100% 一致但有个无语义浮空物"的失败案例。

**字段说明**：

```json
{
  "编号": "el_1",
  "描述": "底部带凹槽的浅蓝白色磨砂玻璃矩形层",
  "参考图语义": "相片下方的标题区/票券副券",
  "主题相关": true
}
```

- `编号`：自动编号 `el_1`、`el_2`...，便于 prompt 阶段决策表引用
- `描述`：形状/位置/材质（**只描述眼睛看到的，不带语义猜测**）
- `参考图语义`：这个元素在参考图主题语境下**最自然的解读**是什么。完全装饰、无语义则填 `"纯装饰"`
- `主题相关`：
  - `true` — 这个元素的语义解读**依赖**于参考图的具体主题 → 换主题时必须**重新判断**
  - `false` — 这个元素是普适装饰（如阴影/背景渐变） → 换主题时可以无脑保留

**填卡纪律**：
- 主体本身不写入此数组（如书本的封面、猴子的身体）；只列**非主体的装饰/辅助元素**
- 一个都没有 → 写空数组 `[]`，不要硬凑
- 不确定语义 → `"参考图语义": "无法解读: <为什么>"`，后续迁移决策时**默认按 主题相关: true 处理**（保守删除）

## 一致性比对规则（评审用）

> ⚠️ **本节已被评审 skill 现行规则取代，仅作字段语义参考**：评审阶段的比对权威是「按图生-评审」SKILL.md——味道字段（光影/媒介/边缘/构图/配色）由 Step C-味 找茬关评判，不再机械比对；Step C-硬 只判「渲染质感门类 + 填充模式 + 空间维度」三轴，且**空间维度（`风格.维度`）不一致 = 修订 + 短路，不是重生成**（防误伤等距扁平）。下表判定后果与现行规则冲突处，一律以评审 SKILL.md 为准。

填完两张 JSON 卡后，**逐字段机械比对**：

| 字段路径 | 比对规则 | 不一致后果 |
|---|---|---|
| `风格.维度` | 必须完全一致 | **一票否决 → 重生成** |
| `风格.渲染` | 必须完全一致 | **一票否决 → 重生成** |
| `风格.填充模式.值` | 必须完全一致 | **一票否决 → 重生成** |
| `风格.光影` | 相邻级允许（仅渐变 ↔ 柔光），跨级 FAIL | 跨级 → 重生成 |
| `风格.媒介.主` | 主材质必须一致 | 不一致 → 重生成 |
| `风格.媒介.次` | 可差异 | 不一致 → 修订 |
| `风格.边缘.锐度` | 必须一致 | 不一致 → 修订 |
| `风格.边缘.接地` | 必须一致 | 不一致 → 修订 |
| `风格.构图` | 相邻档允许，跨 2 档 FAIL | 跨档 → 修订 |
| `风格.背景` | 类型必须完全一致 | 类型不一致 → 修订 |
| `风格.配色.色卡` | **占比=主导 / 次要 的颜色必须在生成图色卡里出现**（颜色名近似匹配，不要求精确 hex） | 缺失 → **重生成**（视觉调性偏离的根因） |
| `装饰元素` | **不参与机械字段比对**；仅供「语义合理性扫描」使用 | — |

**判定优先级**：
1. `维度` / `渲染` / `填充模式.值` 任一不一致 → 直接 FAIL，结论=重生成，结束比对
2. `光影` 跨级不一致 → FAIL，结论=重生成
3. **色卡构成丢失**：参考图色卡里 `占比: 主导` 或 `占比: 次要` 的颜色，在生成图色卡里没有对等项 → 直接 FAIL，结论=重生成（视觉调性 DNA 缺失）
4. 仅 `媒介.次` / `边缘` / `构图` 跨档 / `背景` 类型不一致 → 结论=修订
5. 全字段一致 + 色卡构成完整 → 进入【细节差异】扫描 + 【语义合理性扫描】

**`装饰元素` 的两种用法**：
- **prompt 阶段**：对参考图卡里每个 `主题相关: true` 的元素，做迁移决策——保留/替换/移除（详见 PROMPT-RULES.md Step 2.3）
- **评审阶段**：扫描生成图里是否出现"语义脱锚"的元素（详见评审 SKILL.md Step C-味 分区扫描的「凭空多出元素」脱锚拦截）
