# 按图生 V5.0 — 全自动自迭代 + AI 审美闭环 设计文档

**日期**：2026-06-18
**作者**：Claude + Fengran
**基线版本**：V4.0.4.4（按图生 `e3bb53b` / 评审 `0f46241`）
**目标版本**：V5.0
**预计影响**：按图生 skill + 按图生-评审 skill 双仓库联动改动

---

## 1. 背景与动机

V4.0.4.x 系列稳定运行了一段时间，用户在生产环境暴露出 3 个核心痛点：

1. **picker 浮窗打扰** — 每轮双 tab 生成完后唤起 SwiftUI 浮窗等用户挑 winner，已成为高频中断点
2. **审美维度缺失** — 当前评审 skill 的 9 字段（维度 / 渲染 / 光影 / 媒介 / 填充模式 / 边缘 / 构图 / 背景 / 配色）能保证"风格一致 + 主题贴合"，但**抓不到主体形态层面的造型功力问题**（例如 avatar 主题下：「圆 + 梯形拼接」vs「椭球头 + 有机颈肩过渡」，前者通过、后者也通过，但用户审美明显倾向后者）
3. **三轮断点汇报多余** — 每 3、6、9 轮强制停下汇报状态，打断自迭代节奏；豆包无额度顾虑，无需此类节流

V5.0 的核心目标：**把所有"人类介入点"转成"高质量 AI 自迭代"**，同时补齐审美维度（特别是形态造型力评判）。

## 2. 关键设计决策

### 决策 1：AI 自己判审美是可行的（实验验证）

用户用 Claude 做了实验，prompt 写法是：

> "仅从形态的角度去评价这两张图的优劣，主题是默认头像，不考虑其他要素，仅评判图像本身，给我一句话结论和原因即可"

AI 回答精准命中所有维度：
> "图 2 形态更优——它在保留'默认头像'高度抽象语义的同时，给出了头、颈、肩的解剖比例与转折关系（颅骨弧度、耳廓位置、颈肩过渡），形体语言完整且立体；图 1 则是圆+梯形的纯符号拼接，头颈断裂，肩部为生硬几何切片，缺乏可读的人体结构。"

**3 个起作用的关键 prompt 设计**（V5.0 会复用）：
- **限定单一/明确评判维度**（"仅从 X 角度"）防止 AI 被其他要素干扰
- **给主题词作锚**（"主题是 X"）让 AI 用领域先验做评判
- **两张对比 + 强制原因**（相对判断比绝对打分稳；强制原因防止瞎给结论）

### 决策 2：挑 winner 用「宏观综合判断」而非「仅形态」

用户明确指示："在进入评审前，不要只局限在形态上，还是从宏观角度让主流程自主判断"。

理由：picker 阶段挑的是"两张里相对更好的那张"，是综合判断（形态 + 风格 + 整体观感 + 主题贴合）；如果只盯形态，会丢掉其他维度的信号。

### 决策 3：评审 skill 加「形态评判」独立维度

形态审美作为**单独的硬关卡**加在评审 skill 里。理由：
- 评审 skill 是最终质量守门员，它说不通过就不通过——形态在这里 enforce 才有效力
- 评审已经在评单张 winner，加一个独立维度成本最低
- 评审不合格时已有完整的"重生成"路径可复用

### 决策 4：兜底机制 = 收敛性检测而非固定轮数

不再"每 3 轮停下来汇报"。改成：**连续 3 轮评审结论相同 + 关键差异前三高度重复 → 才汇报**（说明陷入死循环）；否则一直自迭代到通过。

## 4. 详细设计

### 4.1 按图生 skill 改动

#### 4.1.1 去除 picker 主路径，主流程 AI 挑 winner

**当前 Step 3.7 "用户 picker 挑 winner"** → 改为 **"主流程宏观挑 winner"**。

新的 Step 3.7 主路径执行步骤：

1. **强制并行 Read 3 张图**：参考图 + 候选 A + 候选 B（同回合内并行 3 个 Read，禁止跳过）
2. **强制按宏观维度对比输出**（同一回合，结构化文本，不需要 JSON）：

   ```
   候选 A 一句话观察：<风格贴合 + 主体形态 + 整体观感的综合描述>
   候选 B 一句话观察：<同上>
   Winner: A 或 B
   一句话原因：<为什么选这张>
   ```

3. **铁律**：
   - 评判维度是**宏观综合**（风格贴合度 + 主体形态造型力 + 主题贴合度 + 整体观感），**不是仅形态**
   - 必须先输出两张观察，再输出 winner——防止 AI 直接给结论不看图
   - 一句话原因不能虚（"A 更好" 不算原因，"A 主体颈肩过渡比 B 自然" 才算）
4. **挑完执行**：
   ```bash
   rm <落选路径>
   mv <winner 原路径> <temp_dir>/第N轮-winner.png
   ```
5. 进入 Step 4（评审）

**picker 浮窗代码完全废弃**：`bin/picker` 二进制保留（万一未来想恢复），但脚本不再调用。`doubao-gen.mjs` 移除 `--auto-review` 唤起 picker 的分支，handoff JSON 始终返回 `next_action: "main_pick_winner"`。

**对照表**：

| V4.0.4.4 | V5.0 |
|---|---|
| 双 tab 生成完后脚本唤起 picker | 双 tab 生成完后脚本直接返回 candidates，handoff 永远是 `main_pick_winner` |
| picker 浮窗等用户点击 | 主流程并行 Read 3 张图 + 宏观对比挑 winner |
| 用户在 picker 文本框写吐槽（user_complaint） | 移除 user_complaint 机制（用户主动调用时可单独传入，但默认链路不走） |
| picker 启动失败兜底走"主流程兜底挑选" | 主流程挑选 = 唯一路径，不再有"兜底"概念 |

#### 4.1.2 移除三轮断点汇报

**当前 Step 4 唯一例外**：
> 断点汇报：在第 3、6、9... 轮（每 3 轮的整数倍）迭代仍未通过 → 停下来向用户汇报状态

**V5.0 替换为收敛性兜底**：

```
评审结论不为「通过」时，主流程自动进入 Step 4.1 迭代（修订或重生成），
但需先做收敛性检测：

收敛性检测（每轮迭代前自动跑）：
  - 读取最近 3 轮的评审结论（结论 + 关键差异前三）
  - 如果近 3 轮：
    a. 评审结论完全相同（都是「重生成」或都是「修订」）
    b. 且每轮的「关键差异前三」之间相似度 ≥ 80%
       （判定标准：3 条差异里至少 2 条语义相同/高度重叠）
    → 触发"死循环汇报"：停下来告诉用户陷入相同问题循环，建议手动介入
  - 否则：继续自迭代，不打扰用户

收敛性检测在第 4 轮起才可能触发（需要至少 3 轮历史数据）。
```

**实现方式**：在 `/tmp/按图生-评审/{任务ID}/` 目录里维护一个 `iteration-log.json` 文件，每轮评审结束后追加：

```json
{
  "round": 4,
  "结论": "重生成",
  "关键差异前三": ["主体过大", "饱和度偏高", "缺失耳朵"]
}
```

主流程在每次进入 Step 4.1 前先读这个文件做检测。

#### 4.1.3 移除「都不好」分支

picker 没了，「都不好」（`user_picked_neither`）这条路也消失。所有 winner 必从 A/B 中产生（主流程必须选一个，即使两张都不好也选相对好的，后续走评审兜底）。

`doubao-gen.mjs` 的 `next_action` 从 4 个减少到 2 个：
- `main_pick_winner`（默认，主流程挑）
- `await_user`（无 `--auto-review` 时）

### 4.2 按图生-评审 skill 改动

#### 4.2.1 新增 Step C++ 形态审美评判

加在现有 Step C+（语义合理性扫描）之后、Step D（细节差异识别）之前。

**触发条件**：Step C 全字段一致 **且** Step C+ 语义合理性通过（同 Step D 前置）。

**执行步骤**：

```
仅看 winner 一张图，不参照参考图。
prompt（写在评审 skill 内部，调用方无需感知）：

"仅从形态的角度评判这张图，主题是 <theme>，不考虑其他要素，仅评判主体形态。
输出：
- 主体部件枚举：[列出所有可命名部件]
- 形态描述：[一句话客观描述]
- 评级：合格 | 不合格
- 一句话原因：[为什么合格/不合格]

判定标准：
- 部件是否丰富（仅 2 个基础几何元拼成的极简形 → 倾向不合格）
- 部件之间的转折/过渡是否自然
- 主体整体是否具备"经过造型加工"的感觉，而非"占位符级别"
- 必须结合主题词的领域先验（avatar 期望解剖结构；图标可以极简；icon 期望几何精准）"

写入评审 JSON 输出：

"形态评判": {
  "部件枚举": ["头部", "颈部", "肩部", "耳朵"],
  "形态描述": "椭球头 + 有机曲线颈肩过渡，剪影呈葫芦形",
  "评级": "合格",
  "原因": "部件完整，有可读的人体结构"
}
```

**判定后果**：

| 评级 | 后果 |
|---|---|
| `合格` | 进入 Step D 继续走原本细节差异评判 |
| `不合格` | 结论 = `重生成`，覆盖 Step D 的判定；触发 Step 4.1 重生成路径 |

**铁律**：
- **不参照参考图**——纯靠 AI 用主题词领域先验做判断（呼应核心设计决策"用参考图判形态不可行"）
- **不评风格/配色/质感**——这些已在 Step C / C+ 评过，避免重复
- 形态不合格 = 重生成（不是修订）。因为形态平庸是 prompt 层面"主体描述不够具象"的问题，渐进式微调改不动，必须重写 prompt

#### 4.2.2 评审入参 `user_complaint` 退化为可选历史字段

V4.x 的 `user_complaint` 来自 picker 浮窗文本框。V5.0 picker 没了 → 该字段进入"历史保留"状态：
- 主流程默认不再传入
- 评审 skill 仍接受该字段（向后兼容）
- 用户主动调用评审时可手动传入

Step D+「纳入用户主观吐槽」段落保留代码逻辑，但默认链路不再触发。

### 4.3 调用契约变更总结

| 接口 | V4.0.4.4 | V5.0 |
|---|---|---|
| `doubao-gen.mjs` handoff `next_action` | `invoke_review` / `user_picked_neither` / `main_pick_winner` / `await_user` | `main_pick_winner` / `await_user` |
| `doubao-gen.mjs` handoff `user_pick` | `"A"` / `"B"` / `null` | 始终 `null`（picker 没了） |
| `doubao-gen.mjs` handoff `review_payload.user_complaint` | picker 输入透传 | 始终 `null` |
| 评审 skill 入参 | 同 V4 | 同 V4（向后兼容） |
| 评审 skill 出参 | 9 字段评审 + 装饰物语义 + 细节差异 | 上述 + **新增 `形态评判` 字段** |
| 评审 skill 结论 | 通过 / 修订 / 重生成 | 同（但增加 1 条触发"重生成"的路径：形态评级=不合格） |

## 7. 风险与权衡

| 风险 | 缓解 |
|---|---|
| 主流程 AI 挑 winner 失误率 > picker | 强制"两张观察 + 一句话原因"prompt，已被实验验证可靠；万一选错，下游评审会兜底重生成 |
| 评审形态评判误杀（合格图被判不合格） | 形态评级判定标准里强调"结合主题词领域先验"——图标场景下极简形也合格；豆包无额度，重生成成本可接受 |
| 收敛性检测失效，陷入无限循环 | 兜底：连续 3 轮关键差异前三高度重复才汇报。即使检测漏了，用户随时可 ctrl+c |
| 形态评判 prompt 在评审 skill 内部不稳定 | 评审 skill 已强制中文 JSON schema + 必填字段，形态评判 enforce 同样模式，AI 难偷懒 |
