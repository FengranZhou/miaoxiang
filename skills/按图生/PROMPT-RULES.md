# 按图生 Prompt 写作规则（Step 2 完整版 — 中文 JSON 模式）

填完 Step 1.5 参考图分类卡（中文 JSON）后，按本文走 Step 2 写 prompt。**所有 prompt 输出必须是合法中文 JSON**——字段名 + 枚举值 + 描述全部用中文，豆包直接读不需要再翻译。

---

## 2.0 Prompt JSON Schema（中文）

最终喂给 doubao-gen.mjs 的 `--prompt` 参数是一个**合法中文 JSON 字符串**，schema 如下：

```json
{
  "主体": {
    "主体描述": "string (主体名词，如 '一棵树' / '奔跑的运动员' / '铅笔')",
    "类型": "图标 | 插画 | 贴纸 | 海报 | 照片 | 渲染图 (元属性词)",
    "动作": "string | null (动作描述，仅人物/动物等需要)",
    "服装": "string | null (服装描述，仅人物等需要)"
  },
  "风格": {
    "维度": "二维扁平 | 三维渲染 | 摄影 | 手绘",
    "渲染": "矢量图标 | 风格化 | 写实 | 超现实",
    "光影": "无光影 | 仅渐变 | 柔光 | 棚拍光 | 戏剧光",
    "媒介": {
      "主": "扁平UI | 磨砂玻璃 | 黏土 | 塑料 | 金属 | 纸张 | 布料",
      "次": "string | null"
    },
    "填充模式": {
      "值": "实心填充 | 线性描边 | 混合填充",
      "描边连续性": "string | null"
    },
    "边缘": {
      "锐度": "硬边 | 柔边",
      "接地": "浮空 | 接地"
    },
    "构图": "居中铺满 | 居中紧凑 | 居中留白 | 非居中",
    "背景": "纯白 | 纯透明 | 纯色 | 柔和渐变 | 强对比渐变 | 场景",
    "配色": {
      "主色": "string",
      "点缀色": "string | null"
    }
  },
  "装饰元素决策": [
    {
      "参考图元素编号": "el_1",
      "参考图描述": "string (从参考图卡 copy 过来)",
      "决策": "保留 | 替换 | 移除",
      "新描述": "string | null (决策 === '替换' 时必填)",
      "理由": "string (一句话说明为什么这么决策)"
    }
  ],
  "排除": [
    "string (要明确排除的元素/风格关键词列表，可中可英，按豆包好理解的来)"
  ],
  "输出": "单张图片"
}
```

**任何字段不允许缺省**——`null`、空数组 `[]`、空字符串 `""` 都是有效值，但必须显式写出来。

## 2.1 起手式：极简 or 详细？

**判断依据**：主题词的**视觉歧义度**

| 主题类型 | 歧义度 | Prompt 策略 | `主体.主体描述` 示例 |
|---------|--------|------------|------|
| 具象动物/物体 | 低 | 极简：主体 + 风格 + 装饰决策即可 | `"一只可爱的猴子玩偶"` |
| 抽象概念 | 高 | 详细：主体描述拆解为多个特征关键词 | `"一面发光的盾牌，象征勇气"` |
| 复合场景 | 中 | 分层：主体描述含主体+环境+氛围 | `"雾林中的木屋"` |

### V2.9 加固铁则——参考图清晰 + 主题具体 → 强制极简

当**同时**满足以下两个条件时，**禁止**在 `主体.主体描述` 里堆砌冗余形容词：

1. 参考图清晰，单一主体（如一个 icon、一个物体、一张人像）
2. 主题词具体可视（如"铅笔"、"猫咪"、"咖啡杯"，不是"勇气""未来感"这类抽象词）

理由：参考图本身已经把 90% 视觉信息直接喂给豆包了，prompt 的作用是**对齐元属性 + 锚定 1-2 个最易丢失的核心特征**，多写反而稀释信号。

**反例**：参考图是**线性铅笔图标**，把 `主体.主体描述` 写成 `"扁平铅笔图标，深海军蓝渐变，圆头，无投影"`，但**漏写 `填充模式.值: "线性描边"`**，豆包默认按填充实心生成 → 失败。

**正例**：

```json
{
  "主体": {
    "主体描述": "铅笔",
    "类型": "图标",
    "动作": null,
    "服装": null
  },
  "风格": {
    "填充模式": { "值": "线性描边", "描边连续性": "一笔连续闭合" }
  }
}
```

让 `风格.*` 字段承担风格描述，`主体.主体描述` 只锁主体词。

## 2.2 必须遵守的铁律

### 铁律 1：主体.类型 元属性词必须从参考图实际类型挑选

`主体.类型` 必须从下面枚举里选，不要随意写新词：

- UI 类：`图标`
- 平面类：`插画` / `贴纸` / `海报`
- 影像类：`照片` / `渲染图`

不确定时优先选最贴合参考图的那个。

### 铁律 2：输出 字段必须是 "单张图片"

末尾固定 `"输出": "单张图片"`，对应自然语言模式下"生成一张图"。

### 铁律 3：不允许出现 "3D" 字符串于 主体.主体描述

`主体.主体描述` 中禁止字面的 "3D" / "三维" 等维度修饰。维度信息通过 `风格.维度: "三维渲染"` 表达。

### 铁律 3.5：全 prompt 禁用 "2.5D / 二点五维 / 浅浮雕" 等中间档维度词（强制）

**整份 prompt JSON 的任何字段**（`主体.主体描述` / `风格.维度` / `迭代.调整` / `迭代.保持` / `排除` / 任何描述文本）中，**禁止**出现下列词及其近义变体：

- `2.5D` / `2.5d` / `二点五维` / `二点五维分层`
- 用来"半立体"的诱导词：`浅浮雕` / `轻浮雕` / `微浮雕` / `半立体` / `轻拟物立体` / `soft-3D 浅` 之类描述"介于扁平和 3D 之间"的词

**维度只有二元判断**：参考图是不是**渲染器/相机产出的真三维渲染**？
- 是真 3D → `风格.维度: "三维渲染"`
- 否（哪怕带一堆手绘光影：小投影、高光、浮雕感、渐变受光面）→ `风格.维度: "二维扁平"`

**为什么（根因，实战翻车）**：扁平参考图的"立体感"几乎都是**设计师手绘的假立体**（渐变+高光+投影画出来的），不是真 2.5D。一旦 prompt 里写了"2.5D/二点五维/浅浮雕"，**豆包会真的把它渲染成 soft-3D 饱满立体物**（靶心图标被生成成饱满立体回转盘的翻车即此）。手绘光影 ≠ 真 2.5D。要"扁平 + 有光影层次"，就写 `风格.维度: "二维扁平"` + 在 `风格.光影`/`风格.媒介` 里描述手绘渐变/高光，**绝不用维度中间档词去表达**。

**要压住豆包别做立体时的正确写法**：在 `排除` 数组里显式列 `"立体体积感"` / `"饱满立体回转体"` / `"soft-3D 厚度"` / `"真实光照高光斑"`，用排除项压制，而不是用"浅浮雕/2.5D"这种会被豆包当成"给我做点立体"的正向诱导词。

### 铁律 4：主体.主体描述 用具象词，避免抽象形容词

少用 `"可爱"` / `"酷炫"`，多用 `"圆润身体"` / `"霓虹发光"` 等具象词放在 `风格.配色` 或 `风格.媒介` 描述里。

### 铁律 5：卡-prompt 一致性自检（V2 加固，V2.9 / V3.0 扩充，中文 JSON 模式）

写完 prompt JSON 后逐字段核对：

| 参考图卡字段 | prompt JSON 必须 |
|---|---|
| `风格.维度 === "二维扁平"` | prompt 的 `风格.维度` 必须也是 `"二维扁平"`，且 `主体.主体描述` **不得**含 "立体/浮雕/渲染/黏土/体积感" 等词 |
| `风格.维度 === "三维渲染"` | prompt 的 `风格.维度` 必须也是 `"三维渲染"`，且 `主体.主体描述` **不得**含 "扁平/矢量" 等词 |
| `风格.填充模式.值 === "线性描边"` | prompt 的 `风格.填充模式.值` 必须也是 `"线性描边"`，且 `风格.填充模式.描边连续性` 必填 |
| `风格.填充模式.值 === "实心填充"` | prompt 的对应字段必须一致；`描边连续性: null` |
| `风格.光影 === "仅渐变"` 或 `"无光影"` | prompt 的 `排除` 数组里**必须**包含 `"高光斑"` / `"镜面反射"` |
| `风格.边缘.接地 === "浮空"` | prompt 的对应字段一致；`排除` 必须含 `"地面阴影"` |
| `风格.背景 === "纯白"` | prompt 的对应字段一致；`排除` 必须含 `"渐变背景"` / `"场景背景"` |
| `风格.背景 === "柔和渐变"` | `配色` 字段需明确写出渐变方向和颜色 |
| `风格.构图 === "居中留白"` | `主体.主体描述` 描述应**克制**（短词），不堆砌 |
| `风格.构图 === "居中铺满"` | 可以让 `主体.主体描述` 多带一点细节描述 |

字段冲突 → 改 prompt JSON（卡是事实来源，prompt 让步）。

### 铁律 6：装饰元素显式处理（V2.8 加固，必须执行下面 2.3 后再写 prompt JSON）

参考图卡 `装饰元素` 数组里每个 `主题相关: true` 的元素，prompt JSON 的 `装饰元素决策` 数组里**必须**有一条对应记录，包含明确的 `决策`。**不允许默认无脑继承**。

### 铁律 7：色卡守恒（V4.2 强制 — 形态与颜色解耦）

**触发场景**：当某个 `装饰元素决策[].决策 === "移除"` 时，必须独立判断该装饰元素当前承载的**颜色**在参考图色卡里的占比，**不能因为载体被移除就让色卡缺色**。

**判断流程**（对每条 `决策: "移除"` 都要走一遍）：

1. 查参考图卡 `风格.配色.色卡` 数组，找到该装饰元素 `当前载体` 字段指向自己的条目
2. 看该条目的 `占比`：
   - `点缀` → 移除后色卡仍稳定，无需补偿 ✓
   - `次要` 或 `主导` → **不允许直接移除颜色**，必须在 prompt 里给该颜色找**新载体**：
     - 选项 A：让主体本身用这个颜色（如本来"深蓝黑色描边 + 亮绿主体"，移除外框后改为"深蓝黑色主体头部 + 亮绿主体肩膀"）
     - 选项 B：把颜色转给保留下来的装饰元素（如"白色画布"扩充为"深蓝黑色画布"）
     - 选项 C：在主体内增加该颜色作为点缀（如"亮绿主体 + 深蓝黑色细节描边/分割线"）
3. 把补偿方案写进对应 `装饰元素决策[].理由` 字段，明示"该装饰物虽移除，颜色 X 已转载到 Y"
4. **绝对不允许**这种组合：装饰元素决策中有 `占比: 次要/主导` 颜色的载体被移除，但主体/其他保留元素**没有任何**该颜色出现

**反例（V4.2 默认头像 case Round 3-4）**：

参考图色卡：
- 亮草绿色 — 主导（载体：山峰、太阳）
- 深蓝黑色 — 次要（载体：外框描边）
- 纯白 — 点缀（载体：内底）

用户吐槽"不要外框" → 把外框 `决策: "移除"`。
**错误处理**：直接移除外框 → 深蓝黑色从色卡丢失 → 生成图只剩亮绿色 → 与参考图视觉调性偏离
**正确处理**：移除外框 = 移除"描边"这个**形态**，但深蓝黑色是次要色，必须找新载体。选项例：
- 主体头部用深蓝黑色，肩膀用亮绿色 → 双色对比延续参考图调性
- 或主体上有亮绿色块 + 一个深蓝黑色装饰条/分割
- 或在 `装饰元素决策` 里加一条"新增深蓝黑色装饰元素 X 代替原描边的色卡贡献"

**自检 checklist 新增条目**：
- ☐ 对每条 `决策: "移除"` 的装饰元素，是否查过它的颜色占比？
- ☐ 占比 `次要/主导` 的颜色，是否在 prompt 里给了新载体？
- ☐ `主体.主体描述` 或剩余 `装饰元素决策[].新描述` 是否覆盖了参考图色卡里的所有 `占比: 主导` 和 `占比: 次要` 颜色？

## 2.3 装饰元素迁移决策（V2.8 强制 — 中文 JSON 模式）

**这一步是为了堵"风格 100% 一致，但生成图里有个无语义浮空物"的失败模式**（典型案例：按"图片票券"参考图生成"书本"，底部胶囊残留）。

### 2.3.0 首轮决策前置闸门：DNA 抖落 + 加法发散（V5.3.3 新增，必做）

> **V5.3.3 背景（漏洞病根）**：实战暴露——「按图生」把 DNA 抖落 / 减法转移 / 加法发散这套严谨机制**全堆在了 Step 4.1「迭代」阶段**；而**首轮 Step 2.3 写 prompt 时用的还是「主题相关就裸删」的粗糙决策**。结果是首轮系统性丢东西、靠用户 REVISE 才触发迭代里的机制去补——把本该首轮做对的事，拖成「错一轮 + 用户纠错 + 再补」。典型案例：绿沙漏首轮把参考图正面那个**白色￥**当"货币符号·主题无对等"裸删了，但它是**纯白色（次要色）的主要载体**且占据"主体正面正中"视觉锚点位——删 ￥ 形态 = 连带丢了"居中纯白标识"这个色卡 DNA。同轮还把"主体被一圈元素环绕"的构图语言（环绕箭头）只做减法删掉，没问"能不能换沙漏时间语义的环绕元素保留"。

**铁律：首轮做任何 `决策:"移除"` / `决策:"替换"` / `决策:"保留"` 之前，必须先把 Step 4.1.0 发散关的「DNA 抖落 + 加法发散」+ 下面的「继承载体主题合理性拷问」在这里跑一遍——首轮就带 DNA 守恒地决策，而不是"裸移除 / 无脑保留 + 事后靠用户补救"。**

完整机制见「按图生」SKILL.md **Step 4.1.0**（DNA 抖落 / 减法转移 / 加法发散三件套）。首轮在此处至少执行三个强制动作：

1. **DNA 抖落（删/改任何元素前必做）**：盯着参考图里要删/改的这个元素，把它身上扛的全部风格特征**开放穷举**——颜色（是不是 `占比:主导/次要` 色的主要载体？）、是否占据视觉锚点位（主体正面/正中）、材质质感、结构、光学……逐一问「删掉它，这个特征有没有别的载体接住？」**没载体接的特征 → 禁止裸移除**，必须降级为 `决策:"替换"`（换新载体把该特征/锚点接住）。这是色卡守恒铁律 7 的**前置强制版**——铁律 7 是"自检 checklist 里的一条、靠记得查"，这里把它变成"挡在移除决策前面、过不了不许移除"。
2. **加法发散（删任何"服务旧主题的构图元素"时必问一次）**：这个元素代表的**构图语言**（环绕 / 叠层 / 光环 / 描边框）值不值得用**新主题的语义换载体保留**？要保留须过三关（①拟合参考图风格 ②对新主题有真实贡献、非装饰残留 ③克制不抢主体），缺一不加、默认不加——但**必须问过这一句**，不许只做减法。
3. **【核心·V5.4 新增】继承载体主题合理性拷问（对每个"想保留的结构性载体"必做）**：见下方「2.3.0.1」——DNA 抖落只防"删错"（别把 DNA 弄丢），这一问专防"留错"（别把违和形状硬留）。两者是天平的两端，缺了这一端，决策会结构性地偏向"无脑保留参考图自带的外壳"。

跑完闸门（三个动作全过），再进入下面的三选一决策表。

### 2.3.0.1 继承载体主题合理性拷问（V5.4 新增，堵"违和外壳无人评判"）

> **V5.4 背景（漏洞病根）**：实战暴露——现有规则有一个隐含假设「参考图里有的结构性元素 = 天然合法，可无脑继承」，尤其对**主体外层的壳/容器/边框/底板/环绕物**这类扛着风格 DNA 的大载体，默认倾向就是「保留（它扛主导色/材质）」。于是全流程没有任何一关评「这个继承来的形状，配不配当前主题」：脱锚关抓不到它（它不是凭空多出、是参考图本来就有）、味道关反而奖励它（DNA 靠它保住）、形态关只评它内部而不评它本身。典型案例：参考图是**深色房子/盾牌五边形壳 + 内部一个 logo 符号**（那个房子形状是原 app 品牌语义），生成"水杯"时把「壳」当纯风格容器无脑保留、只换内部符号，结果产出**「一个房子形状的壳里装着水杯」**——房子和水杯在语义/形态上毫无关系，这个壳对水杯主题是**冗余甚至违和的外框**，但三道关全放行。这与评审史上「外框冗余」反复发作是同一个根，以前只靠用户 REVISE 事后补，从没在规则层堵住。
>
> **根因**：只有「DNA 抖落」保护"不该丢的"（删载体别弄丢 DNA），缺一个对称的问保护"不该留的"（留载体别硬留违和形状）。而 DNA 抖落甚至会进一步鼓励保留——因为删了要费劲转移 DNA，留着最省事。天平必须补上另一端。

**触发条件**：任何一个**从参考图继承下来的结构性载体**——外壳 / 容器 / 边框 / 底板 / 卡片 / 环绕物（**不含**纯风格的投影 / 背景渐变 / 磨砂叠层这类无形状语义的普适装饰），只要你倾向给它填 `决策:"保留"`，就必须先过这一问。

**强制动作——抛开「它扛 DNA」这个理由，只问它的形状/语义对当前新主题是哪一档**：

| 档位 | 判据 | 决策后果 |
|---|---|---|
| **有贡献** | 载体形状/语义是新主题语义的一部分（如玻璃头像框 × 头像、试管架 × 化学） | 可 `决策:"保留"` |
| **中性** | 载体形状对新主题不贡献也不违和，是通用容器（如圆角方卡 × 任意图标、圆形底盘 × 任意物体） | 可 `决策:"保留"` |
| **违和** | 载体形状带**特定旧主题语义**，套在新主题上会让人疑惑"为什么 X 要装在 Y 里"（如房子/盾牌壳 × 水杯、票券撕边 × 书本、齿轮环 × 花朵） | **禁止 `决策:"保留"`**，必须走下面的处理 |

**判「违和」后的处理（默认删壳 + DNA 转移，用户已拍板此为默认）**：

1. **首选 `决策:"移除"` + DNA 转移**——删掉这个违和形状的载体，但**先对它跑一遍 DNA 抖落**（动作 1），把它扛的主导色 / 材质质感 / 光学等特征**转移到主体本身或新的中性载体**上。例：删深色房子壳 → 把「深墨绿黑主导色 + 磨砂玻璃质感 + 内发光」转移到**水杯本体**（让水杯本身就是深墨绿磨砂玻璃杯、内部薄荷绿发光水线），主体独立站在浅背景上，DNA 不丢、违和外框消失。转移方案写进该条 `理由` 字段，并在 `排除` 数组显式列出被删的旧形状（如 `"房子/盾牌外壳"`）。
2. **次选 `决策:"替换"` 成中性形状**——仅当 DNA 无法干净转移到主体、必须有个外层容器兜底时，才把违和形状**替换**成中性载体（房子五边形 → 圆角方卡），`新描述` 填中性形状 + 它继续承载的 DNA。这是退路，不是首选。

**自检**：做完这一问，回头看 `装饰元素决策` 数组——**有没有任何一个带特定旧主题语义的外壳/边框，被填了 `决策:"保留"`？** 有 → 违反本闸门，回去重判。

**边界**：本问只拦「带**特定旧主题语义**的形状」（房子、盾牌、票券、齿轮…），不误伤中性通用容器（圆角方卡、圆盘、圆环）——中性容器换主题天然成立，照常可保留。判不准是不是"特定语义"时，问一句"一个没看过参考图的人，看到这个形状会不会先想到某个和当前主题无关的东西？"会 → 违和。

### 2.3.1 三选一决策

写 prompt JSON 之前，把 Step 1.5 参考图卡里 `装饰元素` 数组每一条都过一遍，做三选一决策：

| `决策` 值 | 适用条件 | prompt JSON 处理 |
|---|---|---|
| `"保留"` | 元素 `主题相关: false`（普适装饰，如阴影/背景渐变） | `新描述: null`，prompt 模型自然继承 |
| `"替换"` | 元素 `主题相关: true`，但新主题下存在对等元素 | `新描述` 必填新主题下的对等元素描述 |
| `"移除"` | 元素 `主题相关: true`，新主题下无对等元素 OR 强行保留会语义脱锚 | `新描述: null`，且 `排除` 数组里**必须**显式列出该元素被排除 |

**决策原则**：
- 默认保守 → 不确定时选 `"移除"`，而不是 `"保留"`
- `"替换"` 比 `"保留"` 优先级高 → 能找到新主题对等元素就替换，不能再删除
- 任何 `主题相关: true` 的元素都**不允许** `决策: "保留"` 而 `新描述: null` 的组合，必须显式说出"我决定如何处理"

**决策记录示例**（参考图是"图片票券"，新主题是"书本"）：

```json
{
  "装饰元素决策": [
    {
      "参考图元素编号": "el_1",
      "参考图描述": "底部带凹槽磨砂玻璃矩形层（票券副券）",
      "决策": "移除",
      "新描述": null,
      "理由": "书本下面没有'副券'对等物，强行保留会变浮空胶囊"
    },
    {
      "参考图元素编号": "el_2",
      "参考图描述": "主体内白色山+太阳图标占位符",
      "决策": "替换",
      "新描述": "主体内白色横条作为书名标题区",
      "理由": "占位符语义在书本主题下转译为书名横条"
    },
    {
      "参考图元素编号": "el_3",
      "参考图描述": "主体左右圆形凹槽（票券撕线）",
      "决策": "移除",
      "新描述": null,
      "理由": "书本无穿孔特征"
    }
  ]
}
```

**对应的 `排除` 数组**：

```json
{
  "排除": [
    "票券撕线",
    "主体下方磨砂玻璃胶囊",
    "两侧圆形凹槽",
    "立体体积感",
    "镜面高光斑",
    "地面阴影",
    "渐变背景",
    "场景背景"
  ]
}
```

`排除` 由两部分组成：
1. 装饰元素 `决策: "移除"` 的对应中文关键词（**必须**列）
2. 风格层自检铁律 5 衍生的排除词（如 `"立体体积感"` / `"镜面高光斑"` 等）

## 2.5 自检 checklist（写完 prompt JSON 后强制走一遍）

1. ☐ 是合法 JSON？（用 JSON parser 验证）
2. ☐ `主体.主体描述` 不含 "3D" / "三维" 等维度修饰？
3. ☐ `主体.类型` 在中文枚举值内（图标/插画/贴纸/海报/照片/渲染图）？
4. ☐ `风格.*` 9 个字段（含子字段）都填了，没有缺省？
5. ☐ `风格.填充模式.值 === "线性描边"` 时 `描边连续性` 有具体段数描述？
6. ☐ 卡-prompt 一致性自检（铁律 5 表格）逐条核对？
7. ☐ 参考图卡 `装饰元素` 每一条在 `装饰元素决策` 里都有对应记录？
8. ☐ 所有 `决策: "移除"` 的元素，`排除` 里都列出了对应中文关键词？
9. ☐ `输出: "单张图片"` 末尾固定？
10. ☐ JSON 中**没有任何 unicode 转义**（如 `金币`）？序列化时必须用 `jq -c .` 或 `python3 -c "import json,sys; print(json.dumps(json.load(sys.stdin), ensure_ascii=False))"`，**严禁**用默认的 `json.dumps`，否则中文会被 escape 成 `\uXXXX`，豆包读不懂
11. ☐ **色卡守恒检查（铁律 7）**：参考图卡 `风格.配色.色卡` 数组里 `占比: 主导` 和 `占比: 次要` 的每一种颜色，在 prompt JSON 里都能找到承载它的元素（主体本身 / `装饰元素决策[].新描述` / 保留的装饰元素）吗？任何"被移除装饰的次要/主导颜色"必须显式给新载体，不能丢
12. ☐ 用户吐槽 / 评审反馈"不要 X"时，X 是**形态**（如"框框"）还是**颜色**？只移除形态、保留颜色才符合色卡守恒；不要把"形态 + 颜色"作为一个整体一起丢

任一不满足 → 回去补 → 不允许靠"模型自己悟"。
