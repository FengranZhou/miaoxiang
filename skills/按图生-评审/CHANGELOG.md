## v8.4.0（2026-08-04）评审提问加边界：画面主题差异不考虑在内

**一句话**：评审提问从"这两张图属于同一个风格吗？"改成"这两张图属于同一个风格吗？画面主题差异不考虑在内。"——只加一句边界，堵住"把主题题材当风格扣分"的误判。

**病根（实战翻车）**：按图生的设计目标是「按参考图的**风格**、重生成一个**新主题**」——所以生成图的主体题材本来就该和参考图不同（参考图是购物袋、生成图是共享课程包文件夹，这是预期）。但独立进程只被问"是不是同一个风格"，它把**主体题材**（购物袋 vs 文件夹）、**符号/角标内容**（减号 vs 分享箭头）也算进"风格"，连续两轮判"重生成"，理由里明确写"主体应该是购物袋""角标应该是白横线"——把**主题差异**误判成**风格不符**，让"换主题保风格"的正常产物永远过不了关。

**改法**：`review-headless.sh` 的评审 prompt 只加一句「画面主题差异不考虑在内」。不加长篇解释（用户明确要求只要这一句、不要多余展开）。评审自此只看视觉风格/渲染语言（维度/质感/光影/色卡/边缘/填充），不再拿主体题材卡人。

**回退**：`git checkout v8.3.2` 即回本次改动前。

## v8.0.0（2026-07-27）颠覆性升级：评审 = 独立进程一句话宏观评审

**一句话**：评审从"同上下文重流程"彻底改成"独立进程一句话宏观判断"。v7.0.0→v7.3.0 演进的总成（细节见下方 v7.x），契约全变、定版 v8.0.0。

**本仓核心**：
- **新增 `review-headless.sh`**：独立 `claude -p` 进程评审器。`env -u` 剥离 CC 会话变量（真 fresh-eyes + 修 CC 内 fire 崩溃），只问一句「这两张图属于同一个风格吗？若否，微调能修还是得重画？」，结论 Write 到 `<temp_dir>/review-result-第N轮.json`。~30s。
- **SKILL.md 极简**：删 423 行细评流程（强制纪律铁律1-9 / Step A+/B/C-味/C-硬 / 用户吐槽 / Step E / 红旗反例 / 复杂出参 schema），只留：入口拦截块（手动调用也转独立进程，防就地放水）+ 极简入参出参契约 + 一句话评审说明 + 调用方衔接。
- **结论映射**：同风格=是→通过；否+微调→修订(策略B)；否+重画→重生成(策略A)。
- **删废弃文件**：`REVIEW-DISCIPLINE.md`（铁律全文）/ `RED-FLAGS.md`（红旗清单）/ `REVIEW-LOOP-CARD.md`（循环卡）——一句话评审全用不上。

**排查中确认的重要事实**：低分辨率图会让评审误判"同风格"（线宽等细节被糊掉）——喂评审的图务必高清（豆包 2048 原图 OK，CC 窗口贴图可能被压）。另：模型对"是否同风格"的判断在临界带、单次采样有随机性，同图连跑会飘——当前接受，未来若要更稳可上多次采样投票。

**回退**：`git checkout v6.8.0` 即回今天改动前效果，v6.8.0 与 v8.0.0 并存、永久可逆。

## v7.3.0（2026-07-27）彻底极简：评审 = 独立进程一句话宏观提问（删光所有细评流程）

**背景（用户拍板 + 实测数据）**：v7.0~v7.2 试过"独立进程 + 完整细评流程（主题盲测/C-味分区表/C-硬门类双轴/DNA清点）"，实测两大问题：
1. **慢**：完整第②段 ~104-120s，两段共 ~2.5min。且实测大头是"推理流程本身"，不是 Read 44k 文档——所以"内联铁律省文档"的提速尝试失败（反而更慢）。
2. **不准还放水**：一堆规则反而分散模型注意力、诱导它"找理由通过"。同两张明显不同风格的图，带完整流程的进程屡屡判"通过/是"，而用户单开一个干净窗口只问一句"属于一个风格吗"几乎每次判"否"且理由锋利。

**结论**：规则太重 = 又慢又不准。彻底回归一句话。

**改动**：
- `review-headless.sh` 砍成单段——干净独立进程只 Read 两图 + 问一句「这两张图属于同一个风格吗？若否，微调能修还是得重画？」→ 判是=通过 / 否+微调=修订(策略B) / 否+重画=重生成(策略A)。~30s（比原来快 5 倍）。
- SKILL.md 删掉 423 行细评流程（强制纪律铁律1-9 / Step A+ / Step B主题盲测 / Step C-味 / Step C-硬 / 用户吐槽 / Step E / 红旗反例 / 复杂出参 schema），只留：入口拦截块 + 极简入参/出参契约 + 一句话评审说明 + 调用方衔接。
- 出参 schema 瘦身为 `{结论, 同风格判定{同风格,修复方式,理由}, 结论详情, 推送载荷}`。

**排查中确认的一个重要事实（低分辨率会让评审误判）**：对照实验发现——同两张图，headless Read 高清原图判「否」（抓到变宽vs等宽笔画、尖角vs圆头），降到 200px 判「是」（线宽差异糊没了）。**所以喂评审的图必须高清**。CC 窗口贴图可能被压；自动闭环走豆包 2048 原图无此问题。（另注：模型对"是否同风格"的判断本身在临界带、有随机性，同图连跑会飘——这是单次采样的固有局限，当前接受，未来若要更稳可上"多次采样投票"。）

**保留未动**：`env -u` 清 CC 环境（修嵌套崩溃）、入口拦截（手动调用也转独立进程）、按图生主链 Step 5.0 终稿确认弹窗（`bin/confirm`，不在本 skill）。

## v7.2.1（2026-07-27）修两个 v7.2.0 实测暴露的 bug：CC 内 fire 崩溃 + 裸眼粗筛门槛

**Bug A — 从 CC 窗口内 fire 脚本时第②段崩溃**：用户手动 `/按图生-评审`（在一个 CC 会话里）→ 拦截块正确转 fire `review-headless.sh` → 但脚本里的 `claude -p` **继承了父会话的 CC 环境变量**（`CLAUDECODE` / `CLAUDE_CODE_SESSION_ID` / `CLAUDE_CODE_CHILD_SESSION` / `CLAUDE_CODE_ENTRYPOINT` 等），新起的 claude 以为自己还在父会话里 / session 冲突 → 第②段非 0 退出、结果不落盘。（从纯终端手动跑无这些变量，所以之前验证没暴露。）
- **修**：脚本加 `run_clean_claude()`，用 `env -u` 剥离全部 CC 会话变量再跑 `claude -p`——既修崩溃，也让"独立进程"名副其实（不再被父会话环境污染）。

**Bug B — 裸眼快筛门槛失准（先太松、后修过头太严）**：
- v7.2.0 初版 prompt 有句"不看主体、主体不同是正常的"，把判断带向"是" → 明显不同风格的图（鼠标 vs 氛围装饰）草率判「是」（用户 Image #1 vs #2 对比暴露）。
- 第一次修：改成"逐维度对照、任一不同档判否" → **修过头**，同一个任务的第1轮 vs 第2轮 winner（本该同风格，仅背景载体+轻微浮雕差异）也被判「否」，过敏误杀。
- **最终修**：把裸眼快筛明确定位为**粗筛**——只拦"一眼两个世界"的图，不抓同风格内的迭代差异（那是第②段 C-味/C-硬 的活）。判准 = **主色调 + 渲染门类（扁平 vs 写实）+ 整体气质，三样里 ≥2 样根本不搭才判否；单维度差异/迭代微调（线宽/底色/透明棋盘格底/轻微浮雕）一律判是**。
- **双校准点验证**：①网格图同任务迭代 → 判「是」（过敏修好，且判是后正确走完第②段）；②鼠标 vs 氛围装饰 → 判「否」（放松后没漏真差异）。两个都对，门槛卡准。

**同时确认**：Bug A 的修复让 CC 内 fire 走第②段也不崩（校准点①判是后 `stage:full` 退出码 0）。

## v7.2.0（2026-07-27）宏观快筛拆成「裸眼直觉」第①段独立进程

**翻车根因**：v7.1.0 的 Step 0 宏观快筛发生在"已 Read 两份评审文档"之后，文档负担把模型框进"完整评审流程"惯性、钝化第一眼直觉 → 同两张明显不同风格的图，带文档进程草率判「是」、纯裸眼干净窗口判「否」（用户实测截图对比）。详见按图生仓 v7.2.0。

**本仓改动**：
1. **`review-headless.sh` 改两段式**：
   - **第①段宏观快筛** = 极简裸眼直觉进程，prompt 只有两图 + 一句"是不是一个风格"，**不 Read 任何文档**，结论写 `macro-screen-第N轮.json`。判「否」→ 脚本直接用 python 合成重生成短路结论写 `review-result`、不跑第②段。判「是」→ fire 第②段。
   - **第②段完整评审** = Read 评审文档走 主题盲测→C-味→C-硬→出结论（仅①判是才跑）。prompt 里注明"宏观已由前置进程判是，跳过 Step 0"。
   - 握手 JSON 加 `stage` 字段（`macro_short_circuit` | `full`）。
2. **SKILL.md Step 0 降级为"场景 B 专用"**：加说明——自动闭环下 Step 0 已被脚本第①段独立进程取代，进入本文档的第②段进程应跳过 Step 0 直接从 Step B 起走；Step 0 只在用户手动单窗口调用（无脚本分段）时作为流程内第一关。补"只判整体风格不看主体是什么"的判据。

**为什么裸眼进程更准**：无文档 = 无"完整评审流程"惯性牵引 = 第一眼直觉不被"想走完流程"的动机污染。实测跨风格图第①段判否 + 中肯理由 + 30 秒短路（vs 完整流程 1-3 分钟）。

## v7.1.0（2026-07-27）宏观快筛短路前置关 + 删信心评估 / 细节差异收割

**背景**：v7.0.0 把评审移到独立进程后，用户指出——评审里很多机制是为对抗"同上下文放水"加的补丁，现在放水根被拔了，可以精简。梳理后分三类：①防同上下文放水的护栏（可拆）；②防幻觉/看不准（不能拆）；③评审判断力本身（不能拆）。本轮拆①里两块 + 加一个用户要的宏观短路关。

**改动**：
1. **新增 Step 0 宏观风格快筛（短路前置关）**——Read 两图后第一件事，纯第一眼主观直觉答「这两张图属于一个风格吗？」。答**否**→短路：不跑主题盲测/C-味/C-硬，直接出结论（值由评审员据"否的原因"自定：偏离大→重生成、仅调性差→修订），产精简短路 JSON（细评字段 null 占位 + `宏观快筛.否的原因`）。答**是**→加 `宏观快筛.同风格:是` 留痕，照常走完整流程。**收益**：跨风格图一眼毙掉、省掉后三关耗时（实测跨风格图短路比完整流程快明显）。
2. **删「信心评估」整节**——含信心兜底"低→强制重生成"+ 出参 `信心` 字段 + Step E 信心覆盖逻辑。理由：它是防"看不太准姑且放行"的放行动机补丁；独立进程真 fresh-eyes 后动机已消除。铁律 7 编号保留作墓碑。
3. **删「细节差异收割」整节**——含出参 `细节差异` 字段。它只是给下游迭代喂"不阻塞差异"参考料，可有可无。用户吐槽（场景 B）原本往 `细节差异` 追加，改为统一落 `结论详情.关键差异前三`。

**验证（独立进程实跑）**：①同风格图→宏观快筛答「是」→走完整流程→结论通过，`信心`/`细节差异` 字段确认为 null（已删干净）；②跨风格图（鼠标图标 vs 短视频氛围装饰）→宏观快筛答「否」+否的原因落到配色/线宽/构图/背景全维度→短路（主题检查等细评字段 null）→结论重生成。两场景 JSON 均合法落盘。

**修 bug**：`review-headless.sh` prompt 用无引号 heredoc，字段名的反引号被 shell 当命令替换吃空（"不要产出 ` ` / ` ` 字段"变成空）——改用中文引号规避。

**未动**：评审判断力三关（主题盲测 / C-味分区找茬含 DNA 必查+脱锚拦截 / C-硬门类双轴对抗）一字未改。

## v7.0.0（2026-07-27）评审改由独立进程承载 + 新增 `review-headless.sh`

**背景**：评审跑在主生图 CC 窗口同一上下文里会放水（主流程"想让自己的图过"）；subagent 又会幻觉。改为独立 `claude -p` 进程评审——真 fresh-eyes + 真读像素。详见按图生仓 v7.0.0 条目。

**本仓改动**：
1. **新增 `review-headless.sh`**——独立进程评审封装器。接 `--ref --image --theme --temp-dir --round`，拼 prompt 让独立进程自己 Read 本仓文档 + Read 两图 + 走完整流程 + Write 结论 JSON 到 `<temp_dir>/review-result-第N轮.json`，stdout 末行输出握手 JSON。子进程权限 `Read Write`。
2. **Step E 出口改双场景**——A（被脚本独立进程调用）= Write 结论 JSON 到指定文件、不回跳、不 Skill 调用按图生；B（用户手动单窗口调用）= 就地输出 JSON。原「循环卡回跳 / Skill 回跳主流程」废弃。
3. **"第 2+ 轮禁止重复 Read"补例外**——独立进程每轮冷启动、上下文为空，必须每轮都 Read SKILL.md + REVIEW-DISCIPLINE.md；"已在上下文可跳过"只对同一 CC 会话成立。
4. **入参精简**——自动闭环主路径不传 `round_for_payload` / `user_complaint` / `prompt`（脚本不接），评审要纯 fresh-eyes；`user_complaint` 仅用户手动调用（场景 B）时可附。

**评审严格度不变**：评审流程/铁律（Step A→C-味→C-硬→信心→E）一字未改，只换了"在哪个上下文里跑"。fresh-eyes 由"独立进程"从机制上加固，比原来靠"假装第一次看图"的自律更硬。
