# 按图生-评审（v7.3.0 一句话宏观评审 · 独立进程）

## ⛔ 入口拦截（v7.2.0，最高优先级，先于下面一切）——评审必须在独立进程里跑，禁止就地评

**为什么**：评审若在**当前 CC 窗口的上下文里**就地跑，会天然放水——当前上下文往往带着"想让这张图过"的动机 / 已加载的一堆文档会把第一眼直觉框住（实测：同两张不同风格图，就地评草率判「是」，另开干净窗口判「否」）。真正的 fresh-eyes 只有独立进程能给。

**所以，无论你是被谁触发的（用户手动 `/按图生-评审` / 用户说"评审一下" / 任何方式），只要你能凑齐 `参考图路径 + 生成图路径 + 主题`，第一动作就是 fire 独立进程评审脚本，而不是自己在这个窗口 Read 图开评**：

```bash
bash ~/.claude/skills/按图生-评审/review-headless.sh \
  --ref "<参考图绝对路径>" \
  --image "<生成图绝对路径>" \
  --theme "<主题>" \
  --temp-dir "<参考图/生成图所在目录，或任意已存在的目录>" \
  --round 1
```

脚本内部起一个干净独立进程回答那一句宏观提问，末行输出握手 JSON（含 `result_path`）。**你只需 Read `result_path` 那个 JSON，把结论转述给用户即可**——评审判断本身完全由独立进程完成，你不参与评判、不 Read 两张图自己评。

**唯一例外**：脚本不可用 / 报错（`status:error` 或非 0 退出）——此时如实告诉用户脚本失败，可降级为本窗口亲自看两张图、回答"是不是同一个风格"（但要提醒用户"同上下文评审可能偏松"）。

（注：一句话评审的判断逻辑完全在 `review-headless.sh` 的独立进程 prompt 里，本文档不再是评审进程的流程指令——评审进程根本不 Read 本文档。）

## 调用契约

### 入参（调用方必须提供）

脚本 `review-headless.sh` 的入参（命令行参数）：

| 参数 | 说明 |
|---|---|
| `--ref` | 参考图绝对路径（2048px 原图，越清晰越好——低分辨率会让线宽等细节差异丢失） |
| `--image` | 生成图绝对路径 |
| `--theme` | 主题词（当前一句话评审只判风格，不强判主题，但仍透传备用） |
| `--temp-dir` | 结果文件落点目录（跨轮共享） |
| `--round` | 轮次（仅用于结果文件命名，不喂给评审进程） |

**禁止把"应该长什么样"的 prompt 喂给评审进程**：评审只基于纯视觉观察两张图。

> **图务必用高清原图**：实测低分辨率图会把线宽不匀、细节偏差糊掉，导致评审误判"同风格"。CC 窗口贴图可能被压——自动闭环走豆包 2048 原图即可。

### 出参（必须严格按以下中文 JSON 格式回复给调用方）

**出参极简（v7.3.0）**：一句话宏观评审只产出下面这套 schema（`review-headless.sh` 合成、Write 到结果文件）。原复杂 schema（风格味道评判/门类证据/机械比对/主题检查等）随细评流程一并删除。

```json
{
  "结论": "通过 | 修订 | 重生成",
  "备注": "string",
  "同风格判定": {
    "同风格": "是 | 否",
    "修复方式": "微调 | 重画 | 无 (同风格=否时填微调/重画，=是时填无)",
    "理由": "string (如实说清判断依据；若否，说清为何选微调或重画)"
  },
  "结论详情": {
    "值": "通过 | 修订 | 重生成",
    "迭代策略": "A（重生成）| B（修订）| 无",
    "关键差异前三": ["string (若否，为判定理由)"]
  },
  "推送载荷": {
    "图片路径": "<生成图路径>",
    "轮次": null,
    "参考图路径": "<ref_path>",
    "主题": "<theme>"
  }
}
```

`结论` 由「同风格 + 修复方式」映射（见下「评审流程」节）：
- `通过` — 同风格=是 → 调用方进入交付
- `修订` — 同风格=否 + 微调能修 → 策略 B（在当前图基础上渐进调）
- `重生成` — 同风格=否 + 得重画 → 策略 A（完全重写 prompt）

## 评审流程（v7.3.0 极简：一句话宏观评审）

评审已彻底极简为**独立进程问一句宏观提问**，不再有分区表/门类双轴/主题盲测/DNA清点等细评流程（实测那套既慢又不提升质量、反而分散注意力放水；而干净独立进程只问一句话判断更纯粹）。

**评审 = 独立进程回答一句话**：

> **这两张图（参考图 + 生成图）属于同一个风格吗？**
> 若不属于，再判一下：微调能修好（某处颜色/线宽/细节偏了），还是风格根本错了得整张重画？

**结论映射**：
| 判定 | 结论 | 下游策略 |
|---|---|---|
| 同风格 = 是 | `通过` | 交付 |
| 同风格 = 否 + 微调能修 | `修订` | 策略 B（在当前图基础上渐进调） |
| 同风格 = 否 + 得重画 | `重生成` | 策略 A（完全重写 prompt） |

**这套判断由 `review-headless.sh` 在独立 `claude -p` 进程里完成**（真 fresh-eyes、真读像素、~30s），产出下面「出参」schema 的中文 JSON、Write 到结果文件。主流程读结果文件拿结论。**评审进程不 Read 本文档的任何细评规则——本节以下只描述契约，不是给评审进程的流程指令。**

原细评流程（强制纪律铁律 1-9 / Step A+ 视觉证据 / Step B 主题盲测 / Step C-味 风格味道找茬 / Step C-硬 门类双轴 / 用户吐槽处理 / Step E / 红旗反例）已于 v7.3.0 整体删除，历史见 CHANGELOG。

## 与「按图生」系列调用方的衔接

### 调用方发起评审的方式（v7.0.0：独立进程为主路径）

**主路径（自动闭环）**：按图生 Step 4 用 `review-headless.sh` fire 一个独立 `claude -p` 进程，脚本 prompt 已含全部入参 + 结果文件路径。评审进程冷启动、Read 两张图、回答那一句宏观提问、把结论 Write 到结果文件。**评审进程不 Read 本文档任何流程、不知道自己被谁调用、不回跳、不推送**——写文件即交接。

入参（脚本 prompt 里已注入，等价于下列字段）：

```
- ref_path: /abs/path/to/参考图.png
- image_paths[0]: /abs/path/to/第N轮-winner.png
- sampled_index: 0
- theme: <主题>
（review-headless.sh 默认不注入 round / user_complaint / prompt——评审要纯 fresh-eyes）
```

**禁止传入 prompt 字段**。`round_for_payload` / `user_complaint` 在独立进程主路径下不传（脚本不接）；仅**用户手动单窗口调用评审**（场景 B）时可由用户手动附 `user_complaint`。

### 调用方收到中文 JSON 结论后的动作

主流程（按图生 Step 4）**轮询读结果文件** `<temp_dir>/review-result-第N轮.json` 拿到结论后：

| `结论` | 调用方下一步 |
|---|---|
| `通过` | 进入 Step 5（交付） |
| `修订` | 进入 Step 4.1 策略 B（渐进式迭代）|
| `重生成` | 进入 Step 4.1 策略 A（完全重写 prompt JSON）|

调用方不得**重新解释或软化** 结论；本 skill 是评审权威。（v7.0.0：评审权威性由"独立进程 = 真 fresh-eyes"进一步加固——主流程再也无法在同上下文里悄悄放水。）

## 一句话总结

**评审 = 独立进程真看两张图，回答一句「这两张图属于同一个风格吗？」——是=通过，否+微调=修订，否+重画=重生成。快（~30s）、纯粹、不放水。**
